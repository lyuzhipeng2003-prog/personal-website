🔗 去中心化电子投票系统 (基于以太坊) 2025.11 – 2026.01
🔍 Problem：
传统投票系统依赖中心化机构，存在数据篡改、结果不透明风险。社区治理、公司内部选举需要一套公开、不可篡改且可验证的投票方案。
📊 Data：
用户身份及投票记录以智能合约形式存储于以太坊测试链 (Goerli/Sepolia) ，包含选民地址、提案ID、投票选项、时间戳。数据完全上链保证不可篡改。
⚙️ Approach：
使用 Solidity 0.8.0 编写智能合约，设计 User 和 VoteActivity 结构体及权限修饰器；利用 Hardhat 框架进行编译、测试与部署。前端采用 Vue.js + Ethers.js 连接 MetaMask 钱包，实现用户注册、投票执行和结果自动统计。三层架构（前端-合约-区块链）确保端到端透明。
🎯 Outcome/Impact：
完全去中心化的投票应用，投票结果实时上链且任何人可验证，杜绝作弊。系统响应时间 < 3s，支持高并发投票活动。项目代码已归档，可作为 DAO 组织的选举基础设施。
👤 Your Contribution：
独立负责全流程：技术选型、智能合约架构设计、Solidity开发、Hardhat部署、前端交互集成及功能测试，确保系统安全性与稳定性。
合约代码库 (占位) 演示视频/文档
⚡ 香港电动车充电站布局仿真系统 2026.02 – 2026.04
🔍 Problem：
香港电动车数量快速增长，但充电站布局不合理导致“里程焦虑”。需要量化评估候选站点覆盖范围及可达性，为城市规划提供数据决策工具。
📊 Data：
基于 OpenStreetMap 的香港路网数据（节点约2.8万个，边约6.5万条）；充电站候选点坐标；模拟电动车起始位置及行驶需求。数据格式为 CSV 节点/边文件。
⚙️ Approach：
后端使用 Python + Flask，基于 NetworkX 构建图结构并实现 Dijkstra 最短路径算法。Pandas 清洗节点/边数据，提供 RESTful API (充电站列表、路径规划)。前端 Leaflet.js 动态渲染地图，展示站点覆盖范围及最优路径。参与设计覆盖优化算法（贪心选址）。
🎯 Outcome/Impact：
生成可视化交互式决策看板，支持不同选址方案下的覆盖率与平均距离对比。相比随机选址，优化后方案提升核心区域覆盖率约22%。为香港规划署模拟场景提供参考。
👥 Your Contribution：
参与后端开发，实现 Dijkstra 路径规划模块；负责数据预处理（CSV清洗、图构建）；开发基础 API 接口；协助调试地图路径渲染及覆盖计算模块，并编写技术文档。
后端源码 在线演示地图
📊 企业销售数据 ETL 及多维分析看板 2024.07 – 2024.08
🔍 Problem：
某科技公司业务数据存在大量缺失值、异常记录，导致分析效率低；产品团队需要实时了解用户行为趋势及销售关键指标，以优化运营策略。
📊 Data：
公司脱敏销售订单及用户行为日志（约30万行记录，包含交易时间、用户ID、产品类别、金额、地区等）。
⚙️ Approach：

🎯 Outcome/Impact：
仪表板被产品与运营团队日常使用，每周节省约8小时人工处理时间。通过分析发现高潜力地区及用户偏好，支撑了营销活动调整，活动点击率提升12%。
👤 Your Contribution：
独立完成数据清洗脚本、多维分析及 Tableau 看板搭建；与产品协作定义关键指标，撰写最终分析报告。
